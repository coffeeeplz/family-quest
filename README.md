# 가족 퀘스트

가족이 그룹을 만들어 함께 쓰는 퀘스트(할 일)와 코인 앱입니다.
부모가 퀘스트를 등록하고, 자녀가 완료를 알리면, 부모 중 한 명이 확인한 뒤 코인이 적립됩니다.

### 정해 둔 규칙

- 놓친 일: 반복 퀘스트는 최근 3일 치까지 보이고 늦게 하면 절반. 기한 지난 한 번짜리는 끝낼 때까지 남고 코인은 그대로.
- 코인 협상: 자녀가 직접 추가한 한 번짜리 일만. 주고받는 횟수(기본 3번)와 제안 상한(기본 50코인)은 가족 설정에서 바꿈.
  횟수를 다 쓰면 마지막 제안을 받은 쪽이 수락하거나 거절. 거절되면 코인 없는 메모로 남음.
- 자주 쓰는 퀘스트 버튼: 누르면 오늘 할 한 번짜리 퀘스트가 됨. 자녀가 누를 수 있는 버튼은 하루 한 번.
- 상점: 자녀가 신청하면 그만큼의 코인이 묶이고, 부모가 승인할 때 코인이 빠짐. 거절하거나 취소하면 묶인 코인이 풀림.
  승인된 보상은 "받을 보상"에 남아 있다가 부모가 "줬어요"를 누르면 마무리. 잔액은 0 아래로 내려가지 않음.
  구매 제한의 일주일은 월요일부터 일요일까지. 거절된 신청은 횟수에 세지 않음.
- 목표 저금통: 자녀가 보상 하나를 목표로 정하면 홈과 상점에 남은 코인이 보임.
- 뭐먹지: 가족 누구나 메뉴를 올림. 분류는 집밥 / 외식 / 배달 / 간식.
  누군가 먹고 싶어 하는 메뉴는 "먹고 싶어요"에, 아무도 고르지 않은 메뉴는 "메뉴 보관함"에 보임.
  "먹었어요"를 누르면 그날이 기록되고(하루 한 번) 보관함으로 감. 보관함에서 "또 먹고 싶어"를 누르면 다시 올라감.
  같은 이름을 다시 적으면 새로 만들지 않고 있던 메뉴를 올림. 고치기와 지우기는 올린 사람과 부모만.
  링크는 웹 주소(http, https)만 받고 새 창으로 열림.
- 자녀 현황: 부모만 봄. 자녀의 홈과 같은 계산을 쓰므로 자녀가 보는 것과 항상 같음. 읽기 전용이고,
  칭찬 코인 주기와 퀘스트 추가만 여기서 바로 할 수 있음.
- 좌우로 밀기: 왼쪽으로 밀면 다음 쪽. 화면 가장자리 24px 안에서 시작한 동작은 휴대폰의 뒤로 가기와 겹치므로 무시.
  PC 에서는 위쪽 버튼으로 넘김.
- 연속 달성: 그날의 반복 퀘스트를 모두 제때 끝낸 날이 이어진 횟수. 반복 퀘스트가 없는 날은 건너뜀.
  늦게 한 퀘스트와 한 번짜리 퀘스트는 세지 않음. 기본은 3일마다 보너스 10코인.

## Firebase 연결 순서 (한 번만 하면 됨)

1. https://console.firebase.google.com 에서 프로젝트를 만든다. (Google 애널리틱스는 꺼도 됨)
2. **Authentication > 로그인 방법**에서 "Google"과 "이메일/비밀번호"를 켠다.
3. **Firestore Database**를 만든다. 위치는 `asia-northeast3 (서울)`, 모드는 "프로덕션 모드".
4. Firestore의 **규칙** 탭에 이 폴더의 `firestore.rules` 내용을 통째로 붙여 넣고 게시한다.
5. **프로젝트 설정 > 내 앱**에서 웹 앱(`</>`)을 추가하고, 나오는 설정값을 `src/config/firebase.ts` 에 옮겨 적는다.
6. 앱을 올릴 주소가 정해지면 **Authentication > 설정 > 승인된 도메인**에 그 주소를 추가한다.

## 배포 (GitHub Pages)

- 코드는 이 프로젝트 전용 GitHub 저장소에 올린다. `main` 가지에 올라오면 `.github/workflows/deploy.yml` 이
  자동으로 검사(`npm test`)와 빌드를 하고 `https://<계정>.github.io/<저장소>/` 주소에 배포한다.
- 저장소 Settings > Pages 의 Source 는 "GitHub Actions" 로 둔다.
- 배포 주소의 도메인(`<계정>.github.io`)을 Firebase 의 승인된 도메인에 추가해야 Google 로그인이 된다.
- `src/config/firebase.ts` 의 값은 공개돼도 되는 식별자다. 데이터 보호는 `firestore.rules` 가 맡는다.

## 폴더 구조

```
src/
  config/firebase.ts   Firebase 설정값 (비어 있으면 체험 모드)
  backend/             저장소. types.ts 가 약속, firebase.ts 와 demo.ts 가 구현
  domain/              규칙과 계산 (세 구역 나누기, 절반 지급, 협상 차례, 연속 달성, 설정, 초대코드)
  app/                 로그인 상태, 가족 데이터 구독, 화면 틀과 탭
  features/            화면. 기능마다 폴더 하나
    auth/ onboarding/ avatar/ quests/ approvals/ negotiation/ shop/ food/ ledger/ family/ settings/ more/
  ui/                  도트 그림, 버튼, 창, 알림, 좌우로 넘기는 화면 묶음 같은 공용 부품
  styles/tokens.css    색, 글꼴, 치수 (분위기를 바꾸려면 여기만)
  assets/sprites.json  아바타와 아이콘의 도트 그림 데이터
firestore.rules        서버 보안 규칙 (누가 무엇을 할 수 있는지)
tests/                 규칙과 저장소 동작 자동 검사
tools/                 아이콘 생성, 화면 흐름 검사 스크립트
```

새 기능을 붙일 때는 `backend/types.ts` 에 데이터와 메서드를 추가하고,
`features/` 에 폴더를 만들고, `app/Shell.tsx` 에 화면을 한 줄 더하면 됩니다.
아래 탭은 다섯 개까지만 두고, 그보다 늘어나는 화면은 더보기(`features/more/MorePage.tsx`)에 한 줄씩 추가합니다.

## 데이터 구조 (Firestore)

| 위치 | 내용 |
|---|---|
| `users/{uid}` | 내가 속한 가족 |
| `invites/{code}` | 초대코드 (가족, 역할, 만료 시각) |
| `families/{fid}` | 가족 이름, 설정(협상 횟수, 제안 상한, 연속 달성, 칭찬 한마디) |
| `families/{fid}/members/{uid}` | 역할, 이름, 캐릭터, 코인 잔액, 연속 달성 기록, 목표 보상 |
| `families/{fid}/quests/{id}` | 퀘스트 (받는 사람, 코인, 반복, "꼭" 표시) |
| `families/{fid}/runs/{퀘스트id_날짜}` | 수행 기록 (제출 → 승인/반려, 늦음 여부, 한마디) |
| `families/{fid}/ledger/{id}` | 코인 장부 (추가만 가능: 퀘스트, 보너스, 칭찬 코인, 보상 사용은 음수) |
| `families/{fid}/presets/{id}` | 자주 쓰는 퀘스트 버튼 |
| `families/{fid}/proposals/{id}` | 자녀가 직접 추가한 할 일과 코인 협상 |
| `families/{fid}/rewards/{id}` | 상점의 보상 (이름, 가격, 그림, 구매 제한) |
| `families/{fid}/orders/{id}` | 보상 신청 (신청 → 승인/거절 → 받음) |
| `families/{fid}/foods/{id}` | 뭐먹지의 메뉴 (이름, 분류, 링크, 먹고 싶어 하는 사람, 먹은 날) |

코인 보호: 승인, 장부 기록, 잔액 증가는 한 묶음으로 처리되고 부모만 할 수 있습니다.
같은 수행 기록으로는 두 번 지급되지 않습니다.
자녀가 퀘스트를 만들 수 있는 경우는 두 가지뿐입니다: 부모가 낸 금액을 수락했을 때,
부모가 허용한 버튼을 눌렀을 때. 어느 쪽이든 코인은 부모가 완료를 승인한 뒤에만 지급됩니다.

## 개발 명령 (Node.js 20.19 이상)

```
npm install        처음 한 번
npm run dev        개발용으로 띄우기
npm test           자동 검사
npm run build      배포용 만들기 (dist/)
npm run build:demo 파일 하나짜리 체험판 만들기 (dist-demo/index.html)
```
